# Activity 7: Understanding Malicious Attachments

## 1. Objective

The objective of this activity was to understand how malicious email attachments can be used in phishing attacks. I examined suspicious file extensions, macro-enabled documents and the importance of verifying unexpected attachments before opening them.

## 2. Simulated Attachment Analysis

I reviewed three fictional email scenarios to identify potential attachment-related security risks. No actual files were downloaded or opened.

### Example A: Unexpected Invoice

**Filename:** `Invoice.pdf.exe`

**Email context:** The message claimed that an unpaid invoice needed to be opened immediately.

**Observations:**

* The filename contains `.pdf`, which may make it appear to be a document.
* The final extension is `.exe`, which identifies an executable program in Windows.
* The unexpected invoice and pressure to act immediately are additional warning signs.
* Running an untrusted executable could expose a device to malware.

**Assessment:** The attachment was highly suspicious and should not be opened or executed.

### Example B: Macro-Enabled Document

**Filename:** `Staff_Schedule.docm`

**Email context:** The sender requested that the recipient enable macros to view the schedule.

**Observations:**

* The `.docm` extension identifies a macro-enabled Microsoft Word document.
* Macros can run code, and malicious macros may perform harmful actions.
* An unexpected request to enable macros is a significant warning sign.
* The sender and purpose of the document would need to be verified independently.

**Assessment:** The attachment should not be opened or have macros enabled unless it has been appropriately verified and approved under the relevant security procedures.

### Example C: Expected PDF Document

**Filename:** `Meeting_Notes.pdf`

**Email context:** The recipient was expecting meeting notes from a colleague.

**Observations:**

* The `.pdf` extension indicates that the file is intended to be a PDF document.
* The expected context makes the message less unusual, but does not guarantee that it is safe.
* Sender accounts can be compromised, and document files can still contain security risks.
* The message and attachment should be checked according to normal security procedures.

**Assessment:** The attachment cannot be confirmed as safe based on its filename alone.

## 3. Key Findings

This activity highlighted several important points:

1. **File extensions matter.** The final extension can reveal the file type, even when the filename contains another familiar extension.
2. **Executable files can be dangerous.** Running an untrusted executable may allow malware to run on a device.
3. **Macros can introduce security risks.** Malicious macro code may be used to perform harmful actions.
4. **Familiar file types are not automatically safe.** A PDF or document extension does not guarantee that a file is harmless.
5. **Context matters.** Unexpected attachments, urgent demands and unusual instructions should be treated cautiously.
6. **Verification is important.** An attachment's legitimacy should be checked through a trusted channel when there is doubt.

## 4. Security Recommendations

If I receive an unexpected or suspicious attachment, I should:

* Avoid opening or running the file.
* Check the sender and whether the attachment was expected.
* Examine the filename and final file extension without opening the attachment.
* Never enable macros simply because an email requests it.
* Verify unusual requests through a known, trusted contact method.
* Report suspicious attachments using the organisation's approved security-reporting process.
* Follow organisational policies and use approved security tools if further analysis is required.

## 5. Key Lessons Learned

This activity improved my understanding of how malicious attachments can be used to deliver malware or exploit trust.

I learned that executable files, macro-enabled documents and unexpected attachments can present security risks. I also learned that file extensions and sender details are useful clues, but they cannot independently prove that a file is safe or malicious.

The safest approach is to avoid opening suspicious files, verify unexpected requests and follow appropriate security procedures.

## 6. Skills Demonstrated

* Identification of suspicious file extensions
* Basic malware awareness
* Recognition of macro-related security risks
* Phishing attachment risk assessment
* Safe handling of suspicious files
* Documentation of findings and security recommendations

## 7. Safety and Scope

This was a simulated educational exercise using fictional email scenarios and filenames. No attachments were downloaded, opened, executed or submitted to external scanning services. No malware was created or tested.

## 8. Conclusion

Malicious attachments are a potential threat because they can trick recipients into running harmful programs or enabling unsafe code. By checking file extensions, considering the email context, avoiding unexpected attachments and verifying suspicious requests, I can help reduce the risk of malware infection.
