# Activity 3: Examining Suspicious Sender Addresses

## 1. Objective

The objective of this activity was to learn how to examine email sender addresses and identify possible signs of phishing. I also learned why it is important not to trust an email based only on its display name.

## 2. Practical Exercise

I reviewed three fictional email examples to practise identifying suspicious sender details.

### Email A: Account Security Alert

* **Display name:** Microsoft Security
* **Sender address:** `security-alert@example.com`
* **Message:** The email threatened to close the recipient's account within 30 minutes and requested immediate password verification.

**Observations:**

* The display name claimed to represent Microsoft Security, but this was not proof of the sender's identity.
* The message used urgency and a threat to pressure the recipient.
* The request to verify a password was a significant warning sign.
* The sender's identity would need to be verified through a trusted channel.

**Assessment:** The message contained several phishing warning signs.

### Email B: Parcel Delivery

* **Display name:** Delivery Support
* **Sender address:** `parcel-team@example.org`
* **Message:** The email requested an immediate redelivery payment through a link.

**Observations:**

* An unexpected payment request can indicate a possible phishing attempt.
* The request to act immediately could pressure the recipient into making a mistake.
* The display name alone did not establish that the sender represented a legitimate delivery company.
* The sender and delivery request would need to be checked independently.

**Assessment:** The message contained suspicious features that required further investigation.

### Email C: Account Notification

* **Display name:** Bank Support
* **Sender address:** `notifications@example.test`
* **Message:** The email stated that a new notification was available and advised the recipient to sign in through the bank's official app.

**Observations:**

* The display name alone could not verify the sender's identity.
* The message did not request an immediate payment or password through an email link.
* Using the bank's official app is a safer approach than following an unverified email link.
* The sender address would still need to be verified before trusting the message.

**Assessment:** The message had fewer obvious warning signs in its wording, but its authenticity could not be established from the example alone.

*Note: All three addresses and messages were fictional examples used for this exercise. They were not verified real emails.*

## 3. Key Findings

The exercise helped me identify several important points:

1. **Display names can be faked.** A sender can use the name of a trusted organisation without being authorised to represent it.
2. **The actual sender address matters.** I should examine the full email address and pay attention to unusual or misleading domain names.
3. **Urgency is a warning sign.** Threats, deadlines and pressure to act immediately can be used in phishing attacks.
4. **Unexpected requests need checking.** Requests for passwords, payments or sensitive information should be treated cautiously.
5. **One clue is not enough.** A suspicious address does not automatically prove that an email is malicious, and a convincing address does not guarantee that it is safe.
6. **Trusted channels are safer.** I should use an organisation's official website or app, accessed independently, to verify account or payment issues.

## 4. Security Recommendations

* Check the full sender address instead of relying on the display name.
* Look for misspellings, unusual domains and misleading variations in addresses.
* Do not reply with passwords or other sensitive information.
* Avoid clicking unexpected links or opening suspicious attachments.
* Verify unexpected requests through a known official website, app or contact method.
* Follow the organisation's approved process for reporting suspected phishing emails.
* Where appropriate, email authentication technologies such as SPF, DKIM and DMARC can help organisations detect unauthorised or spoofed email. Their presence alone does not guarantee that a message is safe.

## 5. Conclusion

This activity improved my understanding of how sender addresses can help identify potential phishing emails. I learned that display names can be imitated, sender addresses need to be examined carefully, and suspicious messages should be assessed using multiple indicators.

I also learned that I should not make a final decision based on the sender address alone. Further verification and safe security practices are important when investigating suspicious emails.

## 6. Skills Demonstrated

* Phishing awareness
* Sender address inspection
* Identification of social engineering warning signs
* Basic email security analysis
* Security risk assessment
* Documentation of findings and recommendations

## 7. Safety and Scope

This was a simulated learning exercise using fictional email addresses and messages. No real suspicious emails were opened, no links were visited, and no attachments were downloaded. The activity was conducted for educational purposes only.
